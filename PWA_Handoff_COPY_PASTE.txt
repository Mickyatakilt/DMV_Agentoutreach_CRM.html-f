## PART 1 — MAKE IT INSTALLABLE (PWA plumbing)
Add small additive files to the repo root + `<head>` tags in the HTML.

**1. `<head>` tags** (near the existing `<meta name="viewport">` at ~line 5). Replace the viewport with notch-safe version and add the rest:
```html
<meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover">
<link rel="manifest" href="manifest.webmanifest">
<meta name="theme-color" content="#0e2438">
<meta name="apple-mobile-web-app-capable" content="yes">
<meta name="apple-mobile-web-app-status-bar-style" content="black-translucent">
<meta name="apple-mobile-web-app-title" content="Mestate CRM">
<link rel="apple-touch-icon" href="icon-180.png">
```

**2. `manifest.webmanifest`** (repo root):
- `name`: "Mestate Agent Outreach CRM"
- `short_name`: "Mestate CRM"
- `start_url`: `./DMV_Agent_Outreach_CRM.html` (or `.` if you rename to `index.html` — see note)
- `scope`: `/DMV_Agentoutreach_CRM.html-f/`
- `display`: "standalone"
- `background_color`: "#0e2438", `theme_color`: "#0e2438"
- `icons`: 192, 512, and a 512 **maskable**.

**3. App icons (PNG)** — generate from `DISPO_LOGO_URL` in the HTML: `icon-192.png`, `icon-512.png`, `icon-180.png` (apple-touch icon must be **opaque** — Mestate logo centered on **navy #0e2438**, no transparency). Commit to repo root. (Can extract the data-URI and convert with `sips`/ImageMagick.)

**4. `sw.js` service worker** (repo root) — minimal, for installability + fast shell:
- **Cache-first** for the app shell (the HTML + icons).
- **Network-only / NEVER cache** anything to `*.supabase.co` (data must always be live — critical for "don't lose data").
- Include a `VERSION` string; bump it every deploy to bust the old cache.
- Register from the HTML: `if('serviceWorker' in navigator){ navigator.serviceWorker.register('sw.js'); }`

**5. iOS install caveat:** iOS only installs PWAs from **Safari** (Share → Add to Home Screen); no auto prompt. Add a tiny one-time in-app hint shown only on mobile Safari ("Add to Home Screen to use as an app"). Confirm the installed standalone app keeps the login/session (uses localStorage + Supabase session — should persist).

**Milestone:** Mike can Add-to-Home-Screen and it opens full-screen with the Mestate icon.

## PART 2 — MAKE IT MOBILE-FRIENDLY (audit at 375–430px, fix each)
Use the browser MCP (`resize_window` mobile / 375px) and/or the iOS Simulator. Known trouble spots:

- **Wide tables get cut off** (Outreach leads, List Tracking files + contacts sub-table, Probate batch tables, Buyers). Fix: wrap each in an `overflow-x:auto` container so the **page body never scrolls sideways**; better on phone = stacked **card-per-row** layout under `@media (max-width:640px)`.
- **Modals** (`#modal-container`): on mobile make them full-screen / bottom-sheet, body scrollable, with **sticky footer action buttons** (Save/Send always reachable). The long ones: Outreach detail, Probate detail, Dispo form.
- **Floating "Ask AI" FAB** overlaps modal footer buttons on small screens — reposition or hide it when a modal is open on mobile.
- **The NEW Dashboard (SMS Analytics + Probate funnel)** — verify at 375px: the SMS KPI cards (`flex-wrap` w/ `min-width:130px`) should wrap 2-per-row; the date-preset button row should wrap; the daily chart is `overflow-x:auto`; the probate funnel bars are full-width. Make sure the 5 SMS cards + the date bar don't overflow.
- **Inputs:** font-size **≥16px** on inputs/selects (stops iOS auto-zoom); touch targets ≥44px; bigger tap padding on the tiny row action buttons (👁/💬/✎/🗑).
- **Safe areas** (notch/home bar): `env(safe-area-inset-*)` padding on header/footer/FAB with `viewport-fit=cover`.
- **Sidebar:** an off-canvas drawer already exists (`sbIsMobile()` via `matchMedia('(max-width:768px)')`, `.crm-sb-burger`). Verify it works; consider a **bottom tab bar** for the main sections on phones (nicer app feel) — ask Mike first.
- **Dashboard KPI grids + Follow-Up Hub columns:** stack to 1–2 columns on mobile.
- **Also check on mobile:** the login screen, the shared recipient pages (`?shared=lead/task`), and the public deal flyer (`dispoFlyerHTML` — already responsive, lower priority).
